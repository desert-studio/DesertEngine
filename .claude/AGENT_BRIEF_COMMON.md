# Общее для агентов DesertEngine — ЯДРО (читать целиком; ~5 КБ)

Подробности и история — `.claude/AGENT_BRIEF_REFERENCE.md`. **Не читай его целиком**: `grep -n '^##'` и открывай
только нужный раздел (`sed -n 'A,Bp'`). Весь текст, попавший в контекст, оплачивается на КАЖДОМ следующем ходу.

## Проверяй тимлида
Каждое утверждение брифа сверяй по `файл:строка`; неверное — отдельным разделом отчёта. Начни с `git log --oneline -10`.

## Дерево и сборка
- Все пути абсолютные; `pwd` дрейфует между вызовами. Работай только в своём воркти, скретч — своя подпапка.
- Сборка ТОЛЬКО через общий ccache и `-j3`:
  `export CCACHE_SLOPPINESS="pch_defines,time_macros,include_file_mtime,include_file_ctime" CCACHE_COMPRESS=1 CCACHE_BASEDIR=/Users/daniilsavcenko/Desktop/Programming/C++`
  `make <Проект> config=debug -j3 CC="ccache clang" CXX="ccache clang++" > <лог> 2>&1; tail -5 <лог>`
- PCH «modified since the precompiled header» / путь в чужое дерево → удали свои `*.gch`, пересобери.
- Тестовые `.make` есть только после `CI=true premake5 gmake`. Никогда не убивай чужие процессы `make`.
- Ожидание > 5 мин — кусками ≤ 4.5 мин: `for i in $(seq 27); do grep -q "<маркер>" <лог> && break; sleep 10; done`
  (`timeout` на macOS нет). Прогон CI (час+) — одно ожидание `gh run watch` в фоне.

## Контекст — главная статья расхода (60–70 %)
1. Никогда не читай файл целиком: `grep -n` → `sed -n 'A,Bp'`, **не больше ~80 строк за раз**.
2. Длинный вывод (сборка, сюиты, логи, `gh`) — в файл; в контекст только `tail`/`grep` по нему.
3. **Широкий поиск/разведку отдавай субагенту** (Agent, тип Explore): его прочитанное остаётся в его контексте,
   тебе приходит вывод. Сам читаешь только то, что будешь менять.
4. Независимые команды — в ОДИН вызов (`;`). Каждый ход перечитывает весь контекст.
5. Не перечитывай уже прочитанное; держи выводы, а не дампы.
6. Задача выросла больше чем ×1.5 — SendMessage в main сразу.

## Что гонять
- Собираешь и ЗАПУСКАЕШЬ то, до чего дотягивается изменение: свои сюиты + переписи `ComponentReflection`,
  `SettingConsumers`, `ConfigOwnership`, `PointerOwnership` (+`ShaderCacheKey`, если шейдеры).
- Полный свод — только если тронул `Common`, `Engine/Core`, ECS-компоненты, сериализацию или сборочные скрипты.
- Детектор падения — `[  FAILED  ]` И код возврата, не `grep FAILED`.
- Мутации: 3–5 ключевых (главный инвариант), каждая краснеет, восстановление из копии + `touch`.
- Кадр — только если изменение видно на экране (строка запуска — в REFERENCE, раздел «Кадры»).
- НЕ гоняешь: `clang-tidy` (никогда), ASan, сборку Editor, если его не трогал.
- Перед пушем: `PATH="/opt/homebrew/opt/llvm@18/bin:$PATH" bash scripts/CI/CheckFormat.sh <база>` → «clean».

## Что нельзя
- `~/.desertengine/editor.json` — живые настройки владельца: перед КАЖДЫМ запуском редактора `HOME` в свой скретч.
- Не трогать `dev`, не мержить; пушить только свою ветку, если бриф разрешил. Не коммитить бриф и submodule-указатели.
- `Docs/` вне гита и в одной копии. `ci.yml` — только если бриф разрешил.

## Правила кода (контракт `.claude/skills/desert-engine-contract`)
Легаси не держим (старый путь удаляется тем же изменением); ноль TODO/заглушек/мёртвых настроек; один источник
правды; ошибки — `BoolResultStr`/`ResultStr` с именем и числами, никаких молчаливых фолбэков; комментарии —
ПОЧЕМУ, по-английски; 1 ед. = 1 см; миграция формата — в файлах, **сказать тимлиду ДО подъёма версии**;
нулевые C-массивы запрещены (`std::array<T,0>`); имена `far`/`near`/`min`/`max` как переменные — нельзя (MSVC).
Коммиты по-английски.

## Отчёт (≤ ~40 строк; вывод стоит в 5× дороже чтения)
Сделано · чем доказано (числа, сюиты, мутации, пути к кадрам) · сборки и зачем · «что в брифе неверно» · остаток.
