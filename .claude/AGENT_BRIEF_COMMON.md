## Дерево и сборка
- Все пути абсолютные; `pwd` дрейфует между вызовами. Работай только в своём воркти, скретч — своя подпапка.
- Сборка ТОЛЬКО через общий ccache и `-j3`:
  `export CCACHE_SLOPPINESS="pch_defines,time_macros,include_file_mtime,include_file_ctime" CCACHE_COMPRESS=1 CCACHE_BASEDIR=/Users/daniilsavcenko/Desktop/Programming/C++`
  `make <Проект> config=debug -j3 CC="ccache clang" CXX="ccache clang++" > <лог> 2>&1; tail -5 <лог>`
- PCH «modified since the precompiled header» / путь в чужое дерево → удали свои `*.gch`, пересобери.
- Тестовые `.make` есть только после `CI=true premake5 gmake`. Никогда не убивай чужие процессы `make`.
- Ожидание > 5 мин — кусками ≤ 4.5 мин: `for i in $(seq 27); do grep -q "<маркер>" <лог> && break; sleep 10; done`
  (`timeout` на macOS нет). Прогон CI (час+) — одно ожидание `gh run watch` в фоне.

## Контекст — главная статья расхода (замер 2026-09-24: поиск+чтение shell = 60–70 %, паузы > 5 мин = до 30 %)
Стоимость растёт как КВАДРАТ числа ходов: каждый ход перечитывает всё накопленное. Отсюда жёсткие правила.
**Правила 1–3 проверяет хук `.claude/tools/agent_guard.py` на КАЖДОМ твоём вызове: `grep -r`/`rg`/`git grep`/
`find` без `-maxdepth` отклоняются, после 80 вызовов разрешены только git/SendMessage/Write, `sleep` > 270 с и
третья сборка Editor отклоняются. Отказ хука — не ошибка среды, а правило: делай, как он пишет.**

0. **Помощника запускаешь, только если он дешевле тебя**: Explore на haiku (поиск) или рабочий с model: "sonnet"/"haiku" (механические правки по списку, прогоны сюит). На своей модели — нет (хук откажет). Сборка у помощника — по тем же правилам (одна make на машину).
1. **Первый шаг — ОДИН вызов Agent(subagent_type: "Explore", model: "haiku")** «карта задачи» (Explore на haiku в разы дешевле: он только находит, решения принимаешь ты): какие файлы:строки менять, какие
   тесты/переписи задеты, ответ ≤ 60 строк. ПОСЛЕ ЭТОГО `grep -r`/`rg`/`find` по всему дереву в своём контексте
   НЕ делаешь — ищешь только в файлах из карты; понадобилось шире — ещё один Explore. (До 2026-09-24 ни один
   агент Explore не вызвал, и поиск стоил 25–38 % каждой задачи.)
2. **Лимит 55 ходов (цель — 40).** На 40-м ходу, если конца не видно, — остановись на границе шага, запушь, отчитайся:
   вторую половину тимлид даст свежему агенту (две задачи по 60 ходов дешевле одной на 120 почти вдвое).
3. **Ни одной паузы > 5 минут между вызовами** (кэш истекает, весь контекст пишется заново — до 566 тыс. токенов
   за задачу). Сборка Editor — `run_in_background`, затем опрос циклом ≤ 4.5 мин за вызов. Editor собираешь
   НЕ БОЛЬШЕ ДВУХ раз за задачу (после основной работы и финально); итерации — на сюитах.
4. Файл целиком не читай: `grep -n` → `sed -n 'A,Bp'`, ≤ 80 строк за раз. Прочитанное не перечитывай.
5. Длинный вывод (сборка, сюиты, логи, `gh`) — в файл; в контекст только `tail`/`grep` по нему.
6. Независимые команды — в ОДИН вызов. Большие файлы (новый код, тесты) пиши одним Write, не десятью Edit.
7. Задача выросла больше чем ×1.5 — SendMessage в main сразу.

## Правила кода (контракт `.claude/skills/desert-engine-contract`)
